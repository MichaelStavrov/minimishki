# Бэклог — что после заготовки

Шаги 1–29 дают работающий каркас: пустые страницы, CRUD-заглушки, аутентификация.
Здесь — куда двигаться дальше. Порядок внутри приоритета — рекомендуемый.

Продуктовый ориентир — действующий [минимишки.рф](https://минимишки.рф/).
Новая версия на новом домене сохраняет его разделы и услуги, но получает новый дизайн
и может получить новое наполнение. Полная инвентаризация,
формы, праздничный прайс, 102 обнаруженных изображения и разрыв с текущей моделью БД —
в [`09-current-site-audit.md`](./09-current-site-audit.md).

## Приоритет 1. Публичный сайт

Главное, ради чего проект существует: родитель заходит, изучает центр, оставляет заявку.

| Задача | Состав |
|---|---|
| **Дизайн-система** | Палитра детского центра, шрифты, набор компонентов shadcn/ui (Button, Card, Dialog, Input, Select), Header и Footer |
| **Главная страница** | Hero с призывом записаться, блок услуг, блок педагогов, отзывы, контакты, форма заявки |
| **Услуги** | Список и детальная страница — описание, возраст, предложения, цены, расписания, педагоги и кнопка записи; публичные URL подтвердить перед frontend-этапом |
| **Педагоги** | Список `/teachers`, карточка `/teachers/[slug]` |
| **Новости** | Лента `/news` с пагинацией, страница `/news/[slug]` с галереей |
| **Галерея** | `/gallery` — сетка фото с лайтбоксом |
| **Контакты** | Адрес, телефон, карта, часы работы, форма обратной связи |
| **Форма заявки** | Валидация телефона, состояния загрузки/успеха/ошибки, защита от спама |
| **Праздники и прайс** | Аренда, оформление, персонажи, анимационные программы, шоу, дискотеки, мастер-классы и выездные услуги |
| **Отзывы** | Список с пагинацией и форма нового отзыва с премодерацией |
| **Благотворительность** | Список проектов и детальные публикации |
| **Ответы психолога** | Список вопросов и ответов; безопасная форма нового вопроса либо сохранение внешней Google-формы |
| **Политика и cookie** | Рабочая политика обработки данных, согласия в формах и управление cookie |
| **Поиск** | Поиск по услугам и публикациям |

Исторические отзывы, комментарии и вопросы психологу пока не мигрируют. Соответствующие
разделы можно наполнять заново, а перенос истории оставить отдельной задачей.

**Технические задачи по ходу:**

- Компонент изображения: `next/image` + разрешённые домены в `next.config.ts`
- Адаптив: сайт детского центра смотрят с телефона чаще, чем с десктопа
- Скелетоны и `loading.tsx` для маршрутов
- `error.tsx` и `not-found.tsx`

## Приоритет 2. Админка

Чтобы контент правил сотрудник центра, а не разработчик.

| Задача | Состав |
|---|---|
| **Вход** | `/admin/login`, хранение токена, редирект неавторизованных |
| **Layout админки** | Боковое меню, разделы, индикация роли |
| **Заявки** | Таблица с фильтром по статусу, смена статуса, комментарий менеджера. **Самый нужный раздел** |
| **Направления** | CRUD, переключатель публикации, порядок вывода, привязка педагогов |
| **Педагоги** | CRUD, фото, привязка к услугам |
| **Новости** | CRUD, редактор текста, обложка, галерея, дата публикации |
| **Галерея** | Загрузка пачкой, сортировка перетаскиванием, удаление |
| **Пользователи** | Только для `ADMIN`: список, создание менеджеров, смена ролей |
| **Праздничный прайс** | Категории и позиции, цена/единица, длительность, возраст, порядок и публикация |
| **Главная** | Управление промоблоками, сроками показа и материалами витрины |
| **Отзывы** | Очередь модерации, публикация и отклонение; email автора не показывается публично |
| **Благотворительность** | CRUD публикаций и галерей |
| **Ответы психолога** | Вопрос, ответ, дата и публикация с учётом чувствительных данных |
| **Обращения** | Общая обратная связь и заявки с источником, статусом и комментарием менеджера |
| **Настройки сайта** | Контакты, режим работы, соцсети, реквизиты и юридические страницы |

**Технические задачи:**

- Хранение JWT: httpOnly-cookie вместо localStorage (безопаснее против XSS)
- Refresh-токены — сейчас в плане только access
- Middleware Next.js для защиты `/admin/*`
- Оптимистичные обновления в TanStack Query

## Приоритет 3. Загрузка файлов

Без неё админка неполноценна — фото педагогов и галерею придётся вбивать URL'ами.
CRUD шага 20.5 намеренно работает только с готовыми URL и не загружает файлы.

1. **Этап 1:** локальное хранилище — `apps/api/uploads/`, отдача через статику Nest,
   валидация типа и размера, генерация уникальных имён.
2. **Этап 2:** S3-совместимое хранилище (Selectel / Yandex Object Storage / MinIO),
   presigned URL для прямой загрузки с фронта.
3. **Оптимизация:** ресайз при загрузке (`sharp`), генерация превью, WebP.

## Приоритет 4. SEO и аналитика

Детский центр ищут через поиск — без этого сайт не работает.

- `sitemap.xml` и `robots.txt` (в Next.js — через `app/sitemap.ts`, `app/robots.ts`)
- Уникальные `<title>` и `<meta description>` на каждой странице через `generateMetadata`
- Open Graph и Twitter Card для ссылок в мессенджерах
- Микроразметка Schema.org: `LocalBusiness`, `Service`, `Person`
- Яндекс.Метрика и/или Google Analytics
- Подтверждение прав в Яндекс.Вебмастере
- Проверка Core Web Vitals

## Приоритет 5. Уведомления о заявках

Заявка бесполезна, если её увидят через два дня.

- Уведомление в Telegram-бот при новой заявке — самый быстрый и дешёвый вариант
- Дублирование на email (nodemailer + SMTP)
- Автоответ родителю: «заявка принята, свяжемся в течение дня»
- Очередь для отправки, чтобы падение почтового сервиса не роняло API

## Приоритет 6. Деплой

- Отдельный production-bootstrap первого администратора без demo-данных и без
  сброса существующего пароля/роли при повторном запуске
- `Dockerfile` для `apps/api` (multi-stage, prod-зависимости)
- `Dockerfile` для `apps/web` (standalone-режим Next.js)
- `docker-compose.prod.yml` — приложения + postgres + reverse-proxy
- Nginx или Caddy, HTTPS через Let's Encrypt
- Домен, DNS
- Бэкапы БД по расписанию — **обязательно до запуска**, не после
- CI: GitHub Actions — lint, typecheck, build на каждый push
- Переменные окружения на проде через секреты, не в репозитории

## Отложенное из стека

Исключено на старте осознанно (см. [`01-stack.md`](./01-stack.md)), возвращать по мере роста:

| Что | Когда пригодится |
|---|---|
| **Swagger / OpenAPI** | Когда фронт и бэк пишут разные люди, либо появится мобильное приложение |
| **husky + lint-staged** | Когда в проекте больше одного разработчика |
| **commitlint** | Вместе с автогенерацией CHANGELOG |
| **Тесты (Jest)** | Начать с e2e на критичный путь: создание заявки и логин. Юнит-тесты — на бизнес-логику, когда она появится |
| **Rate limiting** (`@nestjs/throttler`) | Перед публичным запуском — обязательно для `POST /api/auth/login` против перебора паролей и CPU-DoS через Argon2, а также для публичной формы заявки |
| **Логирование** (pino) | Когда понадобится разбирать инциденты на проде |
| **Закрыть GHSA-ggr8-5vv4-36mx в `deepmerge-ts`** | `pnpm audit --prod` на 21.08.2026 находит `deepmerge-ts@7.1.5` через `@prisma/config@6.19.3`; исправление есть в 8.0.0. Текущий путь используется конфигурационным CLI Prisma и не достижим из HTTP-кода API, а атака требует рекурсивных объектных графов, которых нет в JSON. Не форсировать несовместимый major через `pnpm.overrides` вслепую: проверить официальный патч Prisma 6 либо закрыть вместе с переходом на Prisma 7 до деплоя |
| **Переход на Prisma 7** | Когда каркас заработает целиком и появится время на миграцию. Проект закреплён на 6.19.3 (решение пользователя на шаге 11). Что придётся сделать: перевести генератор `prisma-client-js` → `prisma-client` с обязательным `output`, вынести строку подключения из `datasource` в `prisma.config.ts` (+ зависимость `dotenv`), добавить сгенерированную папку клиента в `.gitignore`, поправить импорты `@prisma/client` → путь генерации и проверить связку CJS/ESM внутри Nest. Заодно закроется предупреждение про устаревшее поле `package.json#prisma` |
| **Переход на TypeScript 7** | Когда выйдет **7.1** с программным API компилятора. Сейчас 7.0 (нативный, на Go, ~10x быстрее) ломает `nest build`, `ts-node`, `ts-jest` и type-aware правила `typescript-eslint`, поэтому проект закреплён на 6.x — см. [`01-stack.md`](./01-stack.md#политика-версий). Промежуточный вариант, если проверка типов станет узким местом раньше: 6.x для сборки и линта плюс отдельный скрипт `typecheck` на 7.x |
