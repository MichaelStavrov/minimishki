## Специфика проекта «Минимишки»

### 1. Какие файлы ассистент ведёт сам

Общее правило запрещает ассистенту редактировать файлы проекта.
В этом проекте **исключения**:

- `D:\programming\minimishki\AGENTS.md`
- всё в `D:\programming\minimishki\.Codex\plans\`

Остальное — `apps/`, `packages/`, конфиги в корне — только выдачей кода в чат.

**Исключение для код-ревью:** явная просьба пользователя провести ревью считается
разрешением ассистенту самостоятельно исправить все найденные замечания в файлах
ревьюируемой фичи. После правок ассистент повторно проверяет весь diff. Отдельное
согласование каждого исправления не требуется, но область фичи не расширяется и
коммит без отдельной просьбы пользователя не создаётся.

### 2. Пути в выдаче

**Заголовок шага** — Windows-стиль, от `D:\programming\minimishki\`:

```
### Шаг 4 — `D:\programming\minimishki\turbo.json`
```

**Внутри команд** — bash-стиль:

```bash
cd /d/programming/minimishki
```

### 3. Ведение прогресса

После каждого выполненного шага обновлять [`06-progress.md`](./06-progress.md):

- отметить шаг в чек-листе;
- обновить блок «▶️ Текущее состояние» — какой шаг следующий;
- если по ходу принято новое решение — дописать в таблицу «Принятые решения».

### 4. Стабильность принятых решений

Решения из таблицы «Принятые решения» в [`06-progress.md`](./06-progress.md)
**не меняются молча**. Если появилось основание пересмотреть — сначала сказать
об этом пользователю и дождаться решения, потом менять план.

### 5. Соглашения по коду

При написании кода приложений (этапы D–G) сверяться
с [`07-conventions.md`](./07-conventions.md): нейминг файлов, структура модулей Nest,
формат ответов API, границы серверных и клиентских компонентов.

### 6. Версии стека

Мажорные версии зафиксированы в [`01-stack.md`](./01-stack.md#политика-версий).
Перед написанием `package.json` — проверять актуальные минорные:

```bash
pnpm view next version
pnpm view @nestjs/core version
pnpm view prisma version
```
